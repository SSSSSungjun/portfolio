PROJECT 01 · 2026.07 — 08

Bike - book

사내 공용 자전거의 신청·승인·이용·반납을 관리하는 Android·Backend 서비스

ROLE Android & Backend

기술 설계 및 구현

MAIN UI / SERVICE FLOW 대표 화면 또는 서비스 흐름 이미지

OVERVIEW

사내 공용 자전거를 신청하고 관리자가 승인한 뒤 이용·반납까지 이어지는 업무 흐름을 모바일로 옮겼습니다.

Client
Kotlin · Compose · Room · WorkManager · Ktor
Server
Java 17 · Spring Boot · PostgreSQL · JWT
Infra
Docker Compose · GitHub Actions

BACKGROUND

실제 사용을 생각하면 단순 CRUD로 끝나지 않았습니다.

네트워크가 불안정한 상황의 반납 처리, 같은 시간대 예약 충돌, 중복 요청, 사용자별 권한 검증을 함께 고려해야 했습니다.

IMPLEMENT

실패와 중복을 전제로 데이터 흐름을 설계했습니다.

  • Room을 로컬 단일 소스로 사용하고 WorkManager로 오프라인 반납 재전송
  • PostgreSQL exclusion constraint로 시간대 예약 충돌 방어
  • UUID idempotency key와 advisory lock으로 중복 요청 방어
  • JWT·Refresh Token rotation과 서버 측 역할·소유권 검증
RESULT 사내 실제 사용 가능성 검토 단계까지 진행

보안 검토 과정에서 최종 도입되지는 않았지만, 실제 운영 환경의 제약을 개발 단계에서 경험했습니다.

ROLE Full Stack

Backend 중심 설계 및 구현

OVERVIEW

익명성을 유지하면서도 작성자 권한과 데이터 정합성을 지켜야 하는 게시판을 구현했습니다.

Backend

Frontend

Test

WEB UI / LOAD TEST 게시판 화면 또는 부하 테스트 결과 이미지

PROBLEM 01

익명이지만 작성자 권한은 지켜야 했습니다.

프론트 값에 의존하지 않고 쿠키 기반 익명 세션을 사용해 서버에서 소유권을 검증했습니다.

PROBLEM 02

동시에 눌러도 데이터가 깨지지 않게 했습니다.

원자적 조회수 증가와 비관적 잠금, unique constraint를 적용해 수정·좋아요 경쟁 상황을 방어했습니다.

VERIFY

구현 뒤에는 부하로 확인했습니다.

k6 200 VU, 3분간 HTTP 요청 75,336건에서 오류율 0%, HTTP p95 52.89ms를 확인했습니다.
