문제

판단

원격 응답을 기다린 뒤 화면을 바꾸는 대신, 로컬 상태를 먼저 보존하고 전송은 재시도 가능한 작업으로 분리했습니다.

효과

네트워크 상태와 무관하게 사용자의 작업을 보존하고 UI 상태와 재시도 흐름을 분리할 수 있었습니다.

CODE EXCERPTRoom + WorkManager 재전송 흐름실제 프로젝트 코드와 핵심 라인 설명을 이 영역에 추가

02 · CONCURRENCY / IDEMPOTENCY

정상 요청만 가정하지 않고, 동시에 들어오는 요청과 재전송을 기준으로 설계했습니다.

문제

같은 시간대 예약이 동시에 생성되거나, 네트워크 재시도로 같은 요청이 여러 번 처리될 수 있었습니다.

판단

애플리케이션 코드의 사전 조회만으로는 경쟁 상태를 막기 어렵다고 보고 DB 제약과 멱등성을 함께 사용했습니다.

구현

PostgreSQL exclusion constraint와 UUID idempotency key, advisory lock을 이용해 충돌과 중복 처리를 방어했습니다.

효과

요청 순서나 재시도 횟수에 덜 의존하면서 예약 데이터의 정합성을 유지할 수 있도록 했습니다.

CODE EXCERPT예약 충돌 + 멱등 요청 처리DB 제약과 서버 처리 코드 비교를 이 영역에 추가
